THREAT MODELING FOR USABLE SECURITY

Give people enough access — not all access.

Least privilege reduces the blast radius without blocking legitimate work. The design challenge is not “maximum restriction”; it is matching authority to the real task.

GAME 1 · PERMISSION SCULPTOR

Bank teller: serve a customer.

Give the teller enough access to complete the task, but do not hand out unrelated authority.

Select permissions, then test the design.

APT29 / SOLARWINDS

Why UAC bypass matters less when admin rights are absent.

The lecture’s mitigation is simple: remove unnecessary administrator membership. If the user does not permanently hold admin power, bypassing a prompt buys the attacker far less.

APPLEJEUS

Consent helps — but the system still needs a second layer.

Users may click “run” anyway. The design should warn clearly, highlight the safe choice, scan untrusted files and block concealed malicious execution.

02
INTELLIGENCE-LED PENETRATION TESTING

Do not test every attacker. Test the attacker who matters.

Traditional penetration testing finds weaknesses. Intelligence-led testing asks which adversary is most relevant, what they actually do, and whether your defenses survive those TTPs.

GENERIC PEN TEST“What can I break?” Useful, but bounded by the tester’s frameworks and experience.
VS
THREAT-INFORMED TEST“What would APT12 do to us?” Uses CTI, adversary TTPs, critical assets and realistic attack strategy.

04
DATA PRIVACY IN MODERN BUSINESS

Secure data can still be used wrongly.

Security protects data. Privacy governs whether the data should have been collected, how it is used, who receives it and whether the person had meaningful control.

DATA SECURITYCan unauthorized people access, change or destroy it?Confidentiality · Integrity · Availability
DATA PRIVACYWas it collected, stored and shared properly?Purpose · Consent · Transparency · Control

SOCIAL ENGINEERING + THREAT INTELLIGENCE

The easiest system to exploit may be the person using it.

Threat actors use psychology because humans can route around strong technical controls. Defenders can use the same knowledge ethically to test awareness and design better safeguards.

06
ASSESSMENT CAMPAIGNS + MENTAL MODELS

If users misunderstand the interface, the interface is part of the risk.

People bring expectations from every system they have used before. Secure design should align with those expectations, clearly show what actions do, block unsafe behavior and explain why.

AFFORDANCE“What can I do here?”Visible controls should suggest their action.
CONSTRAINT“What am I stopped from doing — and why?”Prevent unsafe action and explain the reason.
CONVENTION“Does this behave like I expect?”Use familiar, consistent patterns.
GAME 6 · FIX THE SECURITY UI

Assessment campaigns are not about embarrassing users. They reveal where real people are likely to fail so the organization can improve training, filtering, interface design and defensive controls.

INTELLIGENCE-BASED DEVSECOPS ARCHITECTURE

Design. Build. Run. Defend. Then feed what you learn back.

A defendable architecture is not a one-time hardening project. It continuously exchanges design knowledge, runtime reality and adversary intelligence.
